# 🎬 抖音素材加工规则

> 本文档定义从"原始采集"到"知识入库"的完整加工标准。
> 所有脚本必须按此规则输出。

---

## 一、文件命名规范

```
{序号}_{日期}_{标题}.md
```

| 字段 | 规则 | 示例 |
|------|------|------|
| 序号 | 该维度的递增编号，3 位补零 | `003` |
| 日期 | `YYYY-MM-DD`（采集日期） | `2026-07-24` |
| 标题 | 清洗后的抖音原标题，去话题标签，限 40 字 | `ClaudeCode配Codex的6种接线方式` |

**完整示例**：`003_2026-07-24_ClaudeCode配Codex的6种接线方式.md`

## 三、MD 模板（必须严格遵守）

```markdown

> 板块 | 可信度 | 来源 | 采集日期

## 📌 一句话总结
（1-2 句话，这视频/文章的核心价值）

## 🔍 核心内容
（3-5 个要点，结构化呈现）

## 🧠 专家升华（AI 辅助生成，需人工审核）
### 技术深度分析
### 更优方案 / 替代思路
### 行业位置
### 实操建议

## 🔗 涉及工具
| 工具 | 用途 | 链接 |

## 💪 行动清单
- [ ] ...

---
*原始素材: [抖音链接] | 采集于 YYYY-MM-DD*
```

## 四、三步加工流程

### 步骤 1：🧹 清洗

| 操作 | 说明 |
|------|------|
| 提取语音核心内容 | 从 ASR 输出中提取有效信息，丢弃语气词和重复 |
| 修正错别字 | "Cloud Code"→Claude Code、"避还"→闭环、"哈尼斯"→harness |
| 丢弃 OCR 噪声 | 重复的水印文字、UI 按钮文字、进度条数字 |
| 保留画面字幕 | OCR 中的讲解字幕（通常出现在画面下方 1/3 处） |

### 步骤 2：🔍 校验升华

| 操作 | 说明 |
|------|------|
| 标注可信度 | 实测 > 官方文档 > 转述 > 推测 > 存疑 |
| 补充技术深度 | 工具背后的原理、为什么这样设计 |
| 补充更优方案 | 有没有更好的工具/方法？对比分析 |
| 补充行业位置 | 这个工具/方法在 AI 生态的哪个位置？竞品是谁？ |
| 补充实操建议 | 什么场景下用？怎么开始？坑在哪里？ |

### 步骤 3：📐 排版输出

| 操作 | 说明 |
|------|------|
| Emoji 标题 | 根据内容类型选 emoji（🔧工具/📖教程/🚀新品/💡技巧/⚠️避坑） |
| 统一模板 | 严格按第三节模板排版 |
| 归档 | 放至对应维度文件夹，更新该维度的序号 |
| 更新 README | 更新 AI知识体系/README.md 的"已精加工"计数 |

## 五、自动加工脚本能做和不能做的

### ✅ 自动脚本能做

- 读取原始 MD（含 ASR + OCR 文本）
- 基础清洗（去语气词、修正常见错别字）
- 判断内容类型（教程/工具/经验/资讯）
- 匹配知识维度
- 生成符合模板的 MD
- 确定序号、命名、归档
- 生成"## 🔍 核心内容"的结构化提取

### ⚠️ 需人工审核

- 错别字修正的准确性
- "## 🧠 专家升华"的深度和技术准确性
- 可信度标注
- 最终排版调整

## 六、配置参数

| 参数 | 值 | 说明 |
|------|-----|------|
| OCR 截图间隔 | 2 秒 | `config.sh: OCR_FRAME_INTERVAL` |
| OCR 最大截图 | 200 帧 | `config.sh: MAX_FRAMES` |
| ASR 模型 | ggml-small.bin | 中文为主 |
| ASR 采样率 | 16kHz | `config.sh: AUDIO_SAMPLE_RATE` |
| 视频下载工具 | yt-dlp | 需 cookie 登录态 |
| Cookie 有效期 | ~30 天 | 过期后需重新登录抖音 |
