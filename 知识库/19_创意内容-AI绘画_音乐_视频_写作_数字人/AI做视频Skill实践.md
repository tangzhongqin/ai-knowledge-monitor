## 🔍 核心内容

### Garden Skills 是什么

- 上线一个月即狂揽 **5000+ GitHub Star** 的开源项目
- 定位：专为 AI 编程代理（Coding Agent）打造的技能库
- 核心理念：**把完整工作流封装成 skill.md**，AI 加载文档 = 加载作者一年的实战经验
- 类比：npm 标准化了代码依赖 → Garden Skills 标准化了工作流

### 四大核心技能（杀手锏）

| 技能 | 功能 | 技术路线 |
|------|------|----------|
| **Web Video** | 代码驱动视频生成，输出 1080P | HTML + GSAP 写画面 → 无头浏览器渲染，代码级精准控制动效 |
| **Web Design** | 输入需求，直接产出可上线的完整前端页面 | AI 代理端到端设计 |
| **GPT Image** | 沉淀提示词规范，告别每次盲猜 prompt | 标准化图像生成流程 |
| **KB Retriever** | 在本地私有知识库中精准检索 | 对接 RAG，知识增强 |

**四者组合 = 一条完整的 AI 内容流水线**

### 使用方式（极简三步）

1. `git clone` Garden Skills 仓库
2. 将所需 skill 文件夹放入 AI 代理的技能目录
3. 用自然语言下达指令（如"把这篇推文做成短视频"），AI 自动读规范 → 写脚本 → 配音 → 渲染，用户只需确认文案和配音

### 解决的痛点

| 传统 AI 做视频的痛点 | Garden Skills 的解法 |
|---------------------|---------------------|
| 工具链割裂，多软件切换 | 统一 agent 技能链，一条指令串起全流程 |
| 模板廉价，千篇一律没质感 | HTML+GSAP 代码级动效控制，告别模板拼凑 |
| AI 只能帮忙写废话脚本 | 完整工作流交给 AI，从创意到成片全覆盖 |
| 每次画图盲猜提示词 | GPT Image skill 沉淀提示词规范 |

### 实操经验补充（来自"学习AI视频的第二天"）

- **AI 生成脚本的坑**：剧情没有冲突，人物没有人设，出来的角色没有美感，台词节奏把控不好
- **人物生成痛点**：角色一会儿变形一会儿穿模，一致性差
- **实用技巧**：找到对应风格的参考图 → 让 AI 反向推导提示词 → 再去生成，事半功倍
- **核心认知**：好剧本需要叙事功底，短期难以速成，应先聚焦在"人物生成质量 + 流程跑通"

## 🧠 专家升华

### 一、技术深度分析：Garden Skills 的创新之处

**1. 视频生成的第三种范式**

当前 AI 视频生成主要分两条路线：
- **扩散模型路线**（Runway Gen-3、Pika、Sora）：从噪声中生成视频帧，优势是创意自由度，劣势是可控性差、风格漂移
- **模板引擎路线**（剪映、CapCut AI）：预制模板 + 素材替换，优势是稳定，劣势是同质化严重

Garden Skills 开创了**第三条路：代码驱动渲染路线** —— 用 HTML + GSAP（GreenSock Animation Platform）编写动画逻辑，再通过无头浏览器（Puppeteer/Playwright）渲染为 1080P 视频。本质上是用前端动画引擎替代视频编辑时间轴。

优势：
- **像素级可控**：每一帧的动画曲线、缓动函数、透明度、位移都可用代码精确控制
- **完全可复现**：代码即项目文件，版本管理天然支持
- **无需 GPU 渲染**：浏览器渲染引擎经过高度优化，消费级设备即可跑
- **动效质量高**：GSAP 是业界标准级动画库，专业动效师也在用

局限：
- 不适合真实世界素材（实拍、3D 渲染、粒子特效）
- 适合的类型：信息图、产品 Demo、数据可视化视频、教程、社交媒体卡点视频

**2. Skill.md 范式的深层逻辑**

Garden Skills 的 skill.md 本质上是一种**可执行知识封装**：
- 它将"人是怎么做视频的"这一隐性知识，编码为 AI 代理可以执行的显式工作流
- 每个 skill.md 不仅包含"做什么"，更包含"为什么这样做""坑在哪里"
- 这是从"Prompt Engineering"到"Workflow Engineering"的升维

对比传统 Prompt：
| 维度 | 传统 Prompt | Skill.md |
|------|-----------|----------|
| 粒度 | 单次对话指令 | 完整工作流封装 |
| 复用性 | 低（每次重新写） | 高（一次编写，反复调用） |
| 知识密度 | 低（依赖模型自身知识） | 高（注入领域专家经验） |
| 可组合性 | 无 | 可像 npm 包一样组合 |

### 二、行业位置：Skill 生态的竞争格局

2025-2026 年，多个平台开始构建 Skill/Plugin 生态：

| 平台 | Skill 机制 | 特点 |
|------|-----------|------|
| **Claude Code** | 内置 Skills + 自定义 skill.md | 开发者工具链深度集成 |
| **Cline** | `.clinerules` + Custom Modes | VS Code 生态 |
| **Cursor** | Rules for AI | IDE 内嵌，规则系统 |
| **Garden Skills** | 独立开源 skill 仓库 | 专注创意内容生成 |
| **GitHub Copilot** | Custom instructions | 编码场景限定 |

**赵明的判断**：未来 AI 代理的竞争"拼的不是模型大小，而是 Skill 库的深度"——这个判断非常前瞻。模型能力正在趋同（GPT-5、Claude 4、Gemini 3 在顶尖场景差异缩小），差异化将来自：
1. **垂直领域知识的封装深度**（谁的 skill 更懂视频创作？）
2. **工作流的可组合性**（能否像搭乐高一样组合 skill？）
3. **知识复利效应**（个人/团队的独家流程能否转化为标准化资产？）

### 三、更优方案探讨

Garden Skills 的 HTML+GSAP 路线可以考虑以下增强：

- **集成 Remotion**（React 视频框架）：React 组件 → 视频，生态更完善，支持音频、字幕、复杂编排
- **接入 AI 配音 + 字幕同步**：如 ElevenLabs TTS + 自动字幕时间轴
- **模板市场机制**：借鉴 npm/VS Code 插件市场，让创作者发布和交易 skill
- **多模态素材注入**：结合 Midjourney/DALL-E 生成插画 → HTML 中引用 → 渲染为视频

### 四、实操建议

- **入门路径**：先 fork Garden Skills → 用 Web Video skill 做一个 30 秒产品 Demo 视频 → 理解 HTML+GSAP 动画模型 → 再尝试组合多个 skill
- **团队落地**：把团队的最佳实践沉淀为内部 skill.md，形成组织的"AI 能力资产"
- **选型建议**：如果做信息图/教程/产品演示类视频，优先 Garden Skills；如果做创意短片/叙事类，用 Runway/Pika 更合适
