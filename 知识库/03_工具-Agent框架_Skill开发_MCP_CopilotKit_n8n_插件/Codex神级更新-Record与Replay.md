# 🎬 Codex 神级更新：Record & Replay -- AI 学习方式从"描述给它听"进化到"做给它看"

> **板块**：`Agent与工具链` | **可信度**：`转述 + 推测（技术原理分析）` | **来源**：[抖音](https://www.douyin.com/video/7653474229572160783) | **日期**：2026-07-23

## 📌 一句话总结

OpenAI Codex 的 Record & Replay 功能，通过屏幕录制 + 多模态理解 + Computer Use 三大能力的组合，将人类的隐性操作知识自动转化为可复用的 Skill，实现了 AI 教学范式的根本性跃迁——从"描述给它听"进化到"做给它看"。

## 🔍 核心内容

### 功能概述

Codex Record & Replay 于 2026 年 7 月 22 日上线。开启后，Codex 会录制你在电脑上的**每一步操作**，理解操作意图，并自动将其转化为一个可重复执行的 **Skill**。下次需要执行同样操作时，直接让 Codex 调用该 Skill 即可，无需再次手动操作。

### 工作流程

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | **Record** | 开启录制，在电脑上正常操作 |
| 2 | **理解** | Codex 通过多模态能力理解屏幕内容和操作意图 |
| 3 | **转化** | 自动生成 Skill（包含 SKILL.md + 验证脚本） |
| 4 | **校验** | 系统通过 `quick_validate.py` 检查 Skill 结构正确性 |
| 5 | **Replay** | 下次说"用那个 Skill 做 XXX"，Codex 自动执行 |

### 实测案例：Ulysses 文章转 Substack 草稿

博主演示了一个完整的 Skill 创建过程：

1. **录制操作**：在 Ulysses 找到文章 → 复制内容 → 打开 Substack → 创建 Newsletter 草稿 → 粘贴 → 提取标题 → 保存为草稿
2. **首次生成**：Codex 生成 `ulysses-to-substack-draft` Skill，但**漏掉了"在正文末尾添加订阅按钮"**这一步
3. **反馈修正**：将遗漏反馈给 Codex，Skill 自动更新
4. **二次验证**：再次执行，Codex 正确滚到正文末尾 → 在最后一段之后放置插入点 → 添加订阅按钮
5. **最终确认**：检查草稿箱，结果完全符合之前手动操作的结果

### 底层能力组合

| 能力 | 作用 | 成熟度 |
|------|------|--------|
| **多模态理解** | 理解屏幕录像中每一帧的语义（按钮、文字、布局） | 已成熟（GPT-4o 级别） |
| **Computer Use** | 复现用户操作（点击、输入、导航） | 快速成熟中 |
| **Skill 框架** | 将操作序列打包为可复用、可校验的 Skill 文件 | Codex 生态特有 |
| **事件流处理** | 将连续操作转化为结构化事件流（event stream） | 核心技术难点 |

### 范式意义

```
旧范式：人类描述需求 → AI 理解文字 → 生成 Skill
新范式：人类演示操作 → AI 观看学习 → 生成 Skill
```

**核心突破**：把不容易用文字描述的**隐性知识**（操作习惯、界面直觉、工作流细节），通过视觉直接"喂"给 AI，实现**隐性知识显性化**。

## 🧠 专家升华

### 技术深度分析

#### 1. 这本质上是"示例编程"（Programming by Demonstration）的 AI 时代重演

Record & Replay 不是凭空发明。它的思想源头可以追溯到 1980 年代的 **Programming by Demonstration (PbD)** 和 2000 年代的 **Robotic Process Automation (RPA)**。二者的核心差异：

| 维度 | 传统 RPA | Codex Record & Replay |
|------|----------|----------------------|
| 理解方式 | 像素/坐标匹配 | 语义理解（知道这是"订阅按钮"而不仅是坐标(300,500)） |
| 泛化能力 | 极弱（换 UI 就崩） | 较强（理解意图后可在变化界面中定位） |
| 错误恢复 | 无 | 可通过自然语言反馈修正 |
| 输出产物 | 静态脚本 | 可进化的 Skill 文件 |

**为什么现在才做出来？** 因为需要三个条件同时具备：GPT-4o+ 级别的视觉理解、可靠的 GUI 操控能力、以及 Skill 生态的基础设施。这三个条件在 2026 年中首次齐备。

#### 2. 事件流（Event Stream）是关键架构设计

从 OCR 字幕片段可以看到，录制的内容并非直接保存为视频，而是转化为**结构化的 event stream**（事件流）。这意味着：

- Codex 不是"录屏回放"，而是**语义化操作序列**
- 每个事件包含：操作类型（点击/输入/滚动/等待）、目标元素（语义标签）、上下文信息
- Skill 实际上是一段"伪代码"：`find("订阅按钮") → scroll_to("正文末尾") → click() → wait_for("确认")`
- 这大幅提升了对 UI 变化的鲁棒性

#### 3. 与 Claude Code Skills / MCP 的对比

| 维度 | Codex Record & Replay | Claude Code Skills + MCP | Cursor Rules |
|------|----------------------|--------------------------|-------------|
| **Skill 创建方式** | 录屏演示 + 自动生成 | 手写 Markdown 指令 + 工具定义 | 手写规则文件 |
| **知识来源** | 视频/视觉（隐性知识友好） | 文字描述（需显性化） | 文字规则 |
| **学习门槛** | 低（会操作就会创建 Skill） | 中高（需理解 Skill 结构） | 低（写规则即可） |
| **适用范围** | GUI 操作、浏览器工作流 | 代码开发、API 调用、文件处理 | IDE 内编码行为 |
| **可移植性** | Codex 生态锁定 | MCP 标准（跨平台） | Cursor 生态 |
| **操作精确度** | 依赖语义定位（可能漂移） | 确定性 API 调用（更可靠） | 代码补全级别 |

### 更优方案 / 替代思路

#### 当前可用的替代方案（非 Codex 用户）

**方案一：Claude Code + Playwright MCP + 自定义 Skill**

```markdown
# SKILL.md 示例：自动发文章到 Substack
1. 使用 Playwright MCP 打开 Substack
2. 定位 "New post" 按钮并点击
3. 从 Markdown 文件读取内容
4. 粘贴到编辑器
5. 提取第一行作为标题
6. 保存为草稿
```

优势：手写 Skill + MCP 工具调用的方式更**确定性强**（API 级别的操作比语义定位更可靠），但创建成本更高。

**方案二：Browser Use + LLM 自动化**

```python
from browser_use import Agent
agent = Agent(
    task="打开 Ulysses，找到文章 X，复制内容到 Substack 新建草稿",
    llm=model
)
agent.run()
```

优势：开源、跨平台、不绑定特定 AI 编码工具；劣势：每次执行都需要消耗大量 token 做视觉理解，不如 Skill 高效。

**方案三：Keyboard Maestro（Mac）+ AI 增强**

传统 Mac 自动化工具 + LLM 辅助判断。适合**固定工作流**，对 UI 变化敏感但速度最快。

#### 我对 Record & Replay 架构的改进建议

1. **Skill 应支持"部分重录"**：目前演示中遗漏步骤需要反馈后整体修正。更好的方案是允许仅重录出错的步骤片段，插入已有 Skill
2. **应支持多路径分支**：同一 Skill 可能因输入不同而有不同操作路径（如 Ulysses 文章含图片 vs 纯文本），目前未看到条件分支能力
3. **需要版本控制**：Skill 修改应有 diff 历史，类似 git blame，追溯哪个版本做了哪步修改
4. **导出为标准格式**：如果将 Skill 导出为 MCP 兼容格式，就可以在 Claude Code 等其他工具中复用

### 行业位置

```
AI 编码工具 Skill 生态分层：

Layer 4: 自动化流水线（未来）─ 多个 Skill 编排、定时触发
Layer 3: Record & Replay ─ 视觉演示 → Skill ← Codex 的位置
Layer 2: 手写 Skill / MCP ─ 文字指令 + 工具调用
Layer 1: 基础代码补全 ─ 行级/块级补全
```

Codex 凭借 Record & Replay 直接跃迁到了 Layer 3，这在 AI 编码工具中是**首个**实现视觉驱动的 Skill 自动创建的产品。其战略意义在于：

- **降低 Skill 创建门槛**：从"需要懂怎么写 Skill"到"会操作就行"
- **覆盖隐性知识**：很多人的工作流藏在肌肉记忆里，视频演示是最自然的表达方式
- **飞轮效应**：用户越用 → Skill 越多 → 生态越强 → 用户越离不开

但须注意：这是平台锁定策略——你的 Skill 只能在 Codex 里用，换工具需要重来。

### 实操建议

#### 如果你想立即用这个功能

1. **先梳理你的重复性工作流**：列出每天/每周会做的重复操作（发布文章、处理邮件、数据录入、报表生成），这些是 Record & Replay 的最佳猎物
2. **从最简单的流程开始**：选一个 5 步以内的操作，录制 → 生成 Skill → 验证
3. **每次只录一个完整闭环**：一个 Skill 做一件事，不要贪大求全
4. **录完后必须测试**：再次执行 Skill，检查是否正确复现，发现遗漏立即反馈修正
5. **为 Skill 写清晰的触发短语**：好的 Skill 名称应该是"用自然语言描述就能触发"的

#### 如果你不用 Codex

- **Claude Code 用户**：学习手写 SKILL.md + MCP 工具调用，虽然门槛更高但更灵活，且 MCP 技能可跨工具复用
- **Cursor/Windsurf 用户**：利用 Rules 功能 + 手动操作文档，效果虽不如但可部分替代
- **通用方案**：Playwright/Browser Use + 自然语言指令，适合一次性任务

#### Skill 投资回报率评估框架

```
ROI = (单次执行时间 × 月执行次数 × 12) - (创建 Skill 时间)

例如：手动发文章到 Substack = 5分钟/次，每月 20 次
      → 年节省：5 × 20 × 12 = 1200 分钟 = 20 小时
      → 创建 Skill：首次录制 + 修正 ≈ 30 分钟
      → ROI: 20h - 0.5h = 19.5h 净节省 ✓
```

对于 ROAS（时间回报）> 5x 的操作，**强烈建议**制作 Skill。
