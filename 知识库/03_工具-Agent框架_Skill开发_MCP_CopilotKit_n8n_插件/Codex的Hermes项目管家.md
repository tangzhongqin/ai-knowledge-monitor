# 🏗️ CodeX 的 Hermes 项目管家：加一层"任务编排层"，让 AI 从聊天工具变成项目执行者

> **板块**：`Agent与工具链` | **可信度**：`转述` | **来源**：[抖音](https://www.douyin.com/video/7636743311356726543) | **日期**：2026-07-23

## 📌 一句话总结

**在 CodeX（Claude Code）前面加一个 Hermes 编排层 —— 负责任务拆解、进度追踪、风险拦截 —— AI 就能从"会聊天的写码工具"升级为"能接项目的执行员"。**

## 🔍 核心内容

### 痛点：CodeX 直接接项目的三大翻车现场

| 问题 | 表现 | 根因 |
|------|------|------|
| **长任务越改越散** | 一开始很猛，后面逻辑越来越乱 | 无结构化任务拆解，上下文窗口被垃圾信息填满 |
| **中断后无法续接** | 窗口一关，回来完全接不上 | 没有外部状态持久化，所有"记忆"随会话消失 |
| **危险操作无刹车** | 删文件、装依赖、大面积改代码 | 模型没有"风险判断"能力，自由度越大越失控 |

### Hermes 三层防护

**第1层：任务拆解（结构化输入）**

不让 CodeX 直接"吃"一整团需求。Hermes 把任务拆成三段：
- ✅ **已完成**（已完成） —— 已经做了什么
- 🔄 **进行中**（进行中） —— 当前正在做什么
- ⏭️ **下一步**（下一步） —— 接下来要做什么

这样 CodeX 每次拿到的不是"做一个电商系统"这种模糊大需求，而是"实现用户登录接口，参数为 email + password，返回 JWT token"这样的**明确小任务**。

**第2层：进度追踪（外部记忆）**

强制维护一个 `Progress.md`，只记录四样东西：
1. 改了哪些文件
2. 最后一个成功命令是什么
3. 现在卡在哪
4. 下一步跑什么

任务中断后，打开 Progress.md 就能**无缝续接**，而不是从零重来。本质上是用 Markdown 文件做了一个**轻量级状态机**。

**第3层：风险拦截（人类确认闸门）**

三类操作 Hermes 会先拦下来让用户确认：
- 🗑️ **删文件** —— 防止误删
- 📦 **装依赖** —— 防止供应链污染
- ✏️ **大范围代码修改** —— 防止"蝴蝶效应"式破坏

这一步特别关键：CodeX 最大的问题不是不会写，而是**自由度太大**，容易越改越乱。

### 最终架构

```
用户需求 → Hermes（拆任务 / 管状态 / 拦风险） → CodeX（执行）
              ↑                                     │
              └──── Progress.md 状态回环 ────────────┘
```

> 一句话：**CodeX 负责执行，Hermes 负责管理。让 AI 从"会聊天的写码工具"变成"能接项目的执行员"。**

## 🧠 专家升华

### 技术深度分析

**1. 这本质上是 "Plan-and-Execute" Agent 模式的朴素实现**

作者无意中复现了学术界和工业界验证过的核心 Agent 模式：

- **Plan（规划）**：Hermes 拆任务 → 相当于 LLM 的 planner 角色
- **Execute（执行）**：CodeX 写代码 → 相当于 executor 角色
- **Reflect（反思）**：Progress.md → 相当于 state / memory

这正是 LangGraph、AutoGen、CrewAI 等框架的核心架构思想。OpenAI 的 Assistants API、Anthropic 的 Claude Code Hooks 系统，也都在往这个方向演进。

**2. 为什么"拆小任务"能解决上下文漂移？**

LLM 的 attention 机制在长上下文中会逐渐"失焦"（Lost in the Middle 现象）。当 CodeX 面对一个模糊大需求时：
- 它需要同时维护"需求理解""架构设计""当前实现状态""未来步骤"四个维度的信息
- 随着对话轮次增加，早期的约束被"遗忘"，后期的"即兴发挥"越来越离谱

Hermes 的解法：**每次只给 CodeX 一段明确的小任务** → 每个 prompt 的上下文都是干净、聚焦的 → 有效利用率大幅提升。

**3. Progress.md 是"外部工作记忆"的极简实现**

认知科学中，人类解决问题依赖**工作记忆（working memory）**，容量有限（7±2 个组块）。LLM 的上下文窗口就是它的"工作记忆"。Progress.md 相当于给 LLM 加了一个**外置硬盘** —— 把不必要常驻上下文的信息（进度、状态、历史命令）卸载到文件里，需要时再读取。

这种做法在工业界被称为 **Checkpointing（检查点机制）**，是长时间 Agent 任务的标配。

**4. 风险拦截是"对齐税"的最小化实践**

AI Safety 领域有一个概念叫 **Alignment Tax（对齐税）** —— 让 AI 更安全所付出的性能/效率代价。Hermes 的第三步本质上是把"对齐税"集中在关键节点上：
- 不拦截每一次代码生成（零摩擦）
- 只在高风险动作前设闸门（删文件、装依赖、改大量代码）
- 相当于一个**最小侵入性的 Human-in-the-loop**

这是一种极高性价比的安全策略：既不过度干预（不像某些工具每步都要确认），也不完全放任（不像早期的 AutoGPT 一夜之间删库跑路）。

### 更优方案 / 替代思路

虽然 Hermes 的方案非常实用，但作为 AI 专家，我认为有几个方向值得升级：

| 维度 | Hermes（当前方案） | 升级建议 |
|------|---------------------|----------|
| **任务拆解** | 手动三段划分 | 用 **LangGraph** 或 **CrewAI** 实现自动任务分解图（DAG），支持并行分支 |
| **进度追踪** | 手工维护 Markdown | 用 **结构化 JSON/YAML** 替代 Markdown，方便程序化读取；或接入 **Mem0 / ChromaDB** 做向量化记忆检索 |
| **风险拦截** | 白名单规则拦截 | 引入 **SkillSpector** 做 16 类安全风险自动扫描（代码注入、依赖投毒、权限提升等） |
| **工具集成** | 仅 CodeX | 接入 **n8n 工作流** 实现"CodeX 执行 → Hermes 检查 → 自动部署 → 通知"全链路 |
| **多任务并行** | 单任务串行 | 用 **cc-fleet subagent** 让多个 CodeX 实例并行处理不同子任务 |
| **记忆持久化** | 单项目 Progress.md | 用 **MemPalace** 跨会话记忆，让 AI 记住"上次这个项目的坑是什么" |

**推荐的成熟方案组合：**

1. **轻量入门**：Hermes（手动）+ Progress.md 模板 —— 零成本起步，视频方案即可
2. **中型项目**：Claude Code Hooks + ChromaDB 向量记忆 + n8n 审批流 —— 半自动化
3. **大型工程**：LangGraph Agent + CrewAI 多 Agent 协作 + Langfuse 全链路追踪 —— 工业级

### 行业位置

这个方案所处的生态位：

```
AI 助手（ChatGPT/Claude 对话）
        ↓
    【Hermes 方案 ← 你在这一层】
        ↓
  AI Agent（Devin / AutoGPT / SWE-Agent）
        ↓
  多 Agent 系统（CrewAI / AutoGen / ChatDev）
        ↓
  AI 软件工厂（完整自动化流水线）
```

**横向对比：**

| 产品 | 定位 | 与 Hermes 差异 |
|------|------|---------------|
| **Devin**（Cognition AI） | 全自动 AI 软件工程师 | 全自动，但贵且不够透明；Hermes 更轻量、可控 |
| **GitHub Copilot Workspace** | IDE 内原生任务规划 | 强绑定 GitHub 生态；Hermes 更通用 |
| **Cursor Agent Mode** | IDE 内 Agent | 功能最接近，但缺少显式的状态文件和风险闸门 |
| **Claude Code Hooks** | Claude Code 原生钩子系统 | 可以部分替代 Hermes 的角色，但需要自行配置 |

**判断**：Hermes 方案处于"AI 助手不够用、AI Agent 太危险"的**最佳折中区间**，特别适合中小型项目和独立开发者。

### 实操建议

**1. 立刻能做 —— Progress.md 模板**

创建项目根目录的 `Progress.md`，格式如下：

```markdown
# 项目进度追踪

## 当前状态
- 阶段：开发中
- 最后更新：YYYY-MM-DD HH:MM

## 已完成
- [x] 初始化项目结构
- [x] 配置 ESLint + Prettier
- [ ] 实现用户认证模块

## 进行中
- 实现 JWT token 刷新逻辑
- 修复登录页面样式错位

## 下一步
- 编写认证模块单元测试
- 接入 Redis 做 token 黑名单

## 最后成功命令
npm run dev

## 已知问题 / 卡点
- CORS 配置在 Safari 下不生效，待调试

## 决策记录
- 2026-07-23: 选择 JWT 而非 Session，理由：无状态利于水平扩展
```

**2. 短期优化 —— 建立风险闸门清单**

在 Claude Code 里明确告诉 Hermes（或通过 CLAUDE.md 配置）：
- "修改超过 3 个文件时，先列出计划让我确认"
- "任何 `rm -rf` / `npm install` / `pip install` 操作前，先解释原因并等待确认"
- "改动核心配置（package.json / Dockerfile / CI 配置）前先沟通"

**3. 中期升级 —— 引入结构化工具**

- 用 **n8n** 搭建审批工作流："CodeX 提出修改 → n8n 推送到你手机 → 你审批 → 继续执行"
- 用 **ChromaDB** 存储历史任务和解决方案，让 AI 可以检索"上次类似的 bug 怎么修的"
- 用 **MemPalace** 实现跨项目记忆："这个项目的技术栈偏好""上次踩过的坑"

**4. 终极形态 —— 全链路自动化**

```
用户说"加一个支付功能"
  → Hermes 拆任务（分析现有代码 → 设计方案 → 拆解子任务）
    → CodeX 执行（逐个完成子任务，每次只拿一个小任务）
      → SkillSpector 安全检查（自动扫描代码风险）
        → n8n 审批流（高风险操作推送到手机）
          → ChromaDB 存储解决方案（下次复用）
            → 自动部署 + 通知
```

## 🔗 涉及工具

| 工具 | 角色 | 类型 | 备注 |
|------|------|------|------|
| **CodeX / Claude Code** | 执行引擎 | AI 编程助手 | 负责具体代码生成和修改 |
| **Hermes** | 任务编排层 | Agent 管家 | 拆任务、管进度、拦风险（自进化 Agent） |
