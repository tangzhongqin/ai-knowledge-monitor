# 🧠 Claude Code 配 Codex 的 6 种接线方式

> **板块**：`AI 编程实操` | **可信度**：`转述` | **来源**：[抖音](https://www.douyin.com/video/7654827698430201115) | **日期**：2026-07-23

---

## 📌 一句话总结

把 **Claude Code**（大脑 / 规划层）和 **Codex**（手 / 执行层）串成 **自动化流水线**，6 种进阶组合机制，每种都是让两个工具互相调用、自动闭环。

---

## 🔌 6 种接线方式

### ① Codex 当子代理（Sub-Agent）

> **难度**：⭐⭐ | **可行性**：✅ 已验证

在 Claude Code 的 `agents` 目录下写一个**自定义 Agent**，内部调用 Codex Client。

| 角色 | 职责 |
|------|------|
| 🧠 **Claude Code** | 接收指令 → 拆解任务 |
| 🤖 **Codex（子代理）** | 默默执行，无需手动切换窗口 |

**操作路径**：`Claude Code → agents 目录 → 自定义 Agent → 调用 Codex Client`

---

### ② MCP 调 Codex（工具调工具）

> **难度**：⭐⭐⭐ | **可行性**：✅ 需自建 MCP Wrapper

把 Codex **包装成 MCP 服务**挂到 Claude Code 上。Claude 像调普通工具一样直接调 Codex，参数和返回值全走 **MCP 协议**，不需要人在中间搬运。

> 💡 **关键点**：这是真正的"工具调工具"玩法——人只负责发指令，中间环节全部自动化。

**涉及组件**：
- `MCP Server`（需自行编写 Codex Wrapper）
- `Claude Code MCP Client`

---

### ③ Worktree 双开（物理隔离）

> **难度**：⭐⭐ | **可行性**：✅ Git 原生能力

| 分支 | 角色 | 任务 |
|------|------|------|
| `main` | 🧠 Claude Code | 规划 + 验收 |
| `worktree-xxx` | 🤖 Codex | 闷头执行 |

两个工作区**物理隔离**，互不污染上下文。合并时通过 `git diff` 对齐，干净又安全。

```bash
# 核心命令
git worktree add ../worktree-codex feature-branch
```

---

### ④ Hooks 自动触发 Codex

> **难度**：⭐⭐⭐ | **可行性**：✅ Claude Code 支持 Hooks

**流程**：
```
Claude 改完代码
    ↓（PostToolUse Hook 自动触发）
Codex 跑测试 → 跑单测 → 生成 fixture
    ↓
整套验证流程系统自己闭环
```

> 💡 **价值**：消除"我是不是该验证一下？"的心智负担，验证环节完全自动化。

**关键配置**：`PostToolUse` 钩子

---

### ⑤ 双模型互审（抓盲点）

> **难度**：⭐⭐⭐⭐ | **可行性**：⚠️ 理论可行，待验证

```
Claude 写完一段 → 丢给 Codex 审
Codex 改完一段 → 丢回 Claude 审
        ↕
   双向循环审查
```

**原理**：两个模型**训练数据不同、偏好不同**，互相换视角能抓出单模型绝对看不见的盲点和坏习惯。

> ⚠️ **存疑点**：作者未给出具体配置方式，属于高阶玩法，需自行设计审查流程。

---

### ⑥ Full Auto 过夜模式

> **难度**：⭐⭐⭐⭐ | **可行性**：⚠️ 取决于任务复杂度

**完整流程**：

| 时间 | 动作 |
|------|------|
| 🌙 **睡前** | 把需求拆成**可验证的子任务** → Codex Full Auto 串行跑 → 每个子任务自动 commit |
| ☀️ **早起** | Claude Code 看所有 diff → 跑 CI → 决定保留 / 回滚 |

> 📦 **产出**：你睡一觉，一组 PR 整整齐齐堆在那里。

> ⚠️ **限制**：适合有测试覆盖、可自动验证的任务。需要人工判断的复杂任务慎用。

## 💪 可操作要点

1. **先练 ①**：在 Claude Code 的 agents 目录写一个调用 Codex 的子代理，体验"不切窗口"的流畅感
2. **再加 ③**：给 Codex 创建独立 worktree，避免执行过程中污染 Claude Code 的上下文
3. **配置 ④**：写一个 PostToolUse hook，让 Codex 在每次 Claude 修改代码后自动跑测试
4. **探索 ⑤⑥**：在熟悉前四种后，尝试双模型互审和过夜模式
