## 1. 是什么

### 一个类比

假设你看完了一本 300 页的书，觉得写得特别好。现在有三个层次的处理方式：

| 层次 | 做什么 | 产出 | 能用吗 |
|------|------|------|:--:|
| 😴 **不处理** | 放回书架/收藏夹 | 无 | ❌ |
| 📝 **做笔记** | 划线、摘抄、写读后感 | 一篇总结文章 | ❌ 需要的时候想不起来去找 |
| 🔧 **蒸馏成 Skill** | 把方法论拆成**可执行的技能模块** | 一组 AI 技能包 | ✅ AI 在你遇到相关问题时**自动调用** |

**仓颉 Skill 做的是第三层的事。**

### 具体来说

你给它一本书的文本（或者一个长视频的字幕），它走完一套严格的流程后，产出一组文件：

```
《穷查理宝典》/
├── BOOK_OVERVIEW.md       # 这本书到底讲了什么（骨架）
├── DIGEST.md              # 不想读全书？看这篇精华就够了
├── INDEX.md               # 所有 skill 的地图 + 关系图
├── GLOSSARY.md            # 关键术语词典（统一的，不是每个 skill 自己定义）
├── 逆向思维/               # 一个独立的 skill
│   ├── SKILL.md           #   完整的技能定义
│   ├── test-prompts.json  #   压力测试用例
│   └── test-results.md    #   测试结果
├── 能力圈/
├── 多元思维模型/
├── 人类误判心理学/
└── ...                    # 大概 10-20 个 skill
```

装到 Claude Code 的 skills 目录之后，当你说"我在纠结要不要接这个项目"，AI 就会自动激活"逆向思维"skill，用芒格的方法帮你分析。

## 2. 核心概念

### "总结"和"蒸馏"到底差在哪

这是整个项目最核心的洞察。绝大多数人（包括大多数 AI 工具）做的事是**总结**，仓颉做的事是**蒸馏**。

| | 总结（Summary） | 蒸馏（Distillation） |
|------|------|------|
| **目的** | 告诉你"讲了什么" | 让你"能用起来" |
| **产出** | 内容概括、复述大意 | 判断框架、操作步骤、边界条件、注意事项 |
| **问的问题** | "这篇文章的主要观点是什么？" | "这里面有什么方法论是我下次遇到类似问题时能用的？" |
| **能否被 AI 调用** | 不能——AI 不知道什么时候该用它 | 能——有明确的 trigger 条件、执行步骤、边界 |
| **类比** | 看完电影写影评 | 把导演的拍摄技法拆成可复用的分镜模板 |

**例子**——同样处理《穷查理宝典》中关于"逆向思维"的内容：

**总结版**（没用）：
> 芒格提倡逆向思维，他认为反过来想问题往往比正面思考更有效。

**蒸馏版**（能用）：
```yaml
name: 逆向思维
description: |
  用户在做决策时反复列举正面理由却理不出头绪时使用。
  不适用于纯信息查询类问题。
  语言信号："要不要""该不该""选哪个""没底""纠结"
trigger: 用户面临决策 + 只想了正面 + 表达犹豫
步骤:
  1. 明确目标："我希望达成的结果是什么？"
  2. 反转问题："什么会导致这个目标彻底失败？" 列出 3-5 条
  3. 对每条失败因素，反推："要避免它，我现在应该做什么？"
  4. 把反推出的行动和正面理由放在一起比较
边界:
  - 不适用于日常琐事（"晚饭吃什么"）
  - 不适用于已有标准答案的问题
  - 作者盲点：过于聚焦风险可能错过高回报机会
```

## 4. 每一步详解

### 阶段 0：读懂全书（5-15 分钟 + AI 处理时间）

**为什么不能跳过**：如果你自己都没读懂，AI 拆出来的就是一堆漂亮废话。

AI 会做四件事：
1. **结构分析**：这本书是什么类型？一句话主旨是什么？主要论点怎么组织的？
2. **术语解释**：作者反复用的那些词（比如芒格的"能力圈"），在作者的语境里到底什么意思？
3. **批判审视**：作者有什么时代局限？什么身份让他有盲点？有什么他没证明就当真理的假设？
4. **应用评估**：哪些内容适合做成 skill？哪些不适合？预估能做几个？

然后**必须给你确认**："骨架我理解对了吗？"——你点头了才继续。

> 💡 **新手注意**：这一步的价值在于——如果一本书的核心主张其实是错的或有严重盲点，后面的 skill 都会带着这个错。所以批判审视（步骤 3）是**最容易被跳过也最重要**的一步。

### 阶段 1：5 个 AI 同时提取（AI 处理时间）

五个 AI 同时读同一本书，各负责一个方向：

| 提取器 | 找什么 | 例子 |
|------|------|------|
| 🧠 框架提取器 | 思维模型、决策框架 | "逆向思维""能力圈""安全边际" |
| 📋 原则提取器 | 行动准则、清单、规则 | "不做空""不懂不投" |
| 📖 案例提取器 | 作者亲自用过的具体案例 | 芒格如何用逆向思维避开可可豆投资陷阱 |
| ⚠️ 反例提取器 | 失败模式、警告 | "嫉妒是七宗罪里最没用的，因为它光吃不做" |
| 📚 术语提取器 | 关键概念定义 | "护城河""锤子综合征" |

每条候选都标注了原文出处（哪章哪节），确保不是 AI 脑补的。

> 💡 **设计智慧**：为什么要 5 个 AI 同时跑而不是 1 个 AI 跑 5 遍？因为**视角不同**——同一个人（AI）读了同一段话，用"找框架"的视角和"找案例"的视角去看，会注意到不同的东西。5 个 extractor prompt 相当于 5 副不同的眼镜。

### 阶段 1.5：三重验证（最关键的环节）

这是仓颉区别于"书摘工具"的核心。每一条候选方法必须通过**全部三项**检验：

**V1 — 跨域验证**：书中至少 **2 个独立语境**下出现过吗？

- ✅ 通过：芒格的"逆向思维"在投资决策、工程设计、教学方法三个独立场景都出现了
- ❌ 不通过：某个漂亮句子只在某一章里提过一次，没有其他证据
- **为什么**：只出现一次的东西可能是作者一时兴起的表达，不是他真正坚持的方法论

**V2 — 预测力测试**：能用它回答**书里没写过的**新问题吗？

- 设计一个书里没直接讨论过的场景
- 用这个方法去分析
- 能得出有意义的结论 → 通过。只能得出废话 → 不通过
- **为什么**：真正的方法必须有外推能力。只能复述书里例子的不是方法，是描述

**V3 — 独特性检验**：把作者名字抹掉，**任何聪明人**都能说出来吗？

- ✅ 通过：段永平的"stop doing list"——主动列不做什么，反常识
- ❌ 不通过："要珍惜时间"——常识，AI 本身就知道，不需要专门做成 skill
- **为什么**：常识不需要 skill 承载。只有作者的**差异化见解**才值得固化

> 💡 **通过率**：一本方法论密集的书（如《穷查理宝典》）通常只有 25-50% 的候选能通过。不是越多越好——宁缺毋滥。

淘汰的候选也不会删除，而是放进 `rejected/` 目录并注明淘汰原因。你可以随时捞回来。

### 阶段 2：RIA++ 结构化构造

把每个通过验证的方法论，变成 AI 能理解的六段式结构：

```
┌─────────────────────────────────────────┐
│ R — Reading (原文引用)                    │
│  ≤150 字，必须标注出处                    │
├─────────────────────────────────────────┤
│ I — Interpretation (用自己的话重写)        │
│  目标是：没读过原书的人看完这段能理解方法   │
├─────────────────────────────────────────┤
│ A1 — Past Application (书中案例)          │
│  作者亲自用这个方法处理过的真实案例         │
├─────────────────────────────────────────┤
│ A2 — Future Trigger (触发条件) ★ 最关键   │
│  用户在什么情境下需要这个 skill？           │
│  会说什么样的话？                         │
│  和哪些相邻 skill 不同？                   │
├─────────────────────────────────────────┤
│ E — Execution (可执行步骤)                │
│  1-2-3 步，每步有明确的完成标准            │
├─────────────────────────────────────────┤
│ B — Boundary (边界)                      │
│  什么时候不要用？有什么失败模式？           │
│  作者有什么盲点？                         │
└─────────────────────────────────────────┘
```

> 💡 **A2 为什么最关键**：一个 skill 写得再好，如果 trigger（触发条件）写得太宽或太窄，要么永远不被调用，要么在不该用的时候乱用。A2 决定了这个 skill 是"活的"还是"死的"。

### 阶段 3：Zettelkasten 链接

找出 skill 之间的关系：

- **A 依赖 B**：用"逆向思维"之前可能需要先用"能力圈"确认自己在这个领域有没有判断力
- **A 对比 B**："安全边际"和"集中投资"在表面上矛盾，但实际上是互补的
- **A 组合 B**："多元思维模型"+"逆向思维"可以联合使用

然后生成 `INDEX.md`（总览地图 + 引用关系图）和 `GLOSSARY.md`（所有 skill 共享的术语词典，不在每个 skill 里重复定义）。

> 💡 **为什么要做这一步**：10 个互不关联的 skill 是散弹，10 个有引用关系的 skill 是网络。网络的价值随节点数指数增长。

### 阶段 4：压力测试

**这一步是仓颉最独特的环节。** 不是"做完了就完了"——要验证。

为每个 skill 设计 8-12 条测试 prompt，分三类：

| 类型 | 数量 | 例子 |
|------|:--:|------|
| ✅ 应该触发 | 3-5 条 | "我要不要接这个项目？列了一堆好处还是没底" → 应该激活逆向思维 |
| ❌ 诱饵题 | 2-3 条 | "帮我查一下这个 API 参数" → 纯查询，不应该激活任何决策 skill |
| ⚠️ 边界题 | 1-3 条 | "晚饭吃什么？" → 虽然是"决策"但太琐碎，不应该激活 |

**硬性要求**：诱饵题中至少 1 条是"应该触发同书另一个 skill"的跨 skill 混淆题。因为同一本书拆出的 10+ 个 skill 之间互相抢调用，是部署后最常见的真实故障。

测试方式：用一个**没参与过蒸馏过程、不知道预期答案**的独立 AI 去答题。如果通过率低于 80%，**回炉重做阶段 2**，不打补丁。

### 阶段 5：交付

最后两步：
1. 生成 `DIGEST.md`——面向人类读者的精华长文。"不想读全书？看这篇就够了。"
2. 把通过测试的 skill 安装到你的 `~/.claude/skills/` 目录——**没有这一步，前面的所有工作都是白做**。

## 5. 新手怎么用

### 最小入门路径（30 分钟）

**第一步：准备工作**

```bash
# 已经克隆到本地了
cd /Users/tangzhongqin/Documents/学习/待命名/cangjie-skill-study
```

你需要准备：
- 📖 一本你想蒸馏的书的文本（PDF/EPUB/TXT 都行，可以先转成纯文本）
- 🎬 或者一个长视频的字幕文件（推荐搭配 [video-downloader](https://github.com/kangarooking/kangarooking-skills/tree/main/video-downloader) skill 先下载+转写）

**第二步：安装仓颉 Skill 到自己**

把 `SKILL.md` 复制到你的 Claude Code skills 目录：

```bash
# 用户级（所有项目可用）
cp SKILL.md ~/.claude/skills/cangjie-skill.md

# 或者项目级（只在当前项目可用）
mkdir -p .claude/skills/
cp SKILL.md .claude/skills/cangjie-skill.md
```

**第三步：对 Claude Code 说**

> "帮我把《XXX》蒸馏成 skill"

Claude Code 会自动加载仓颉 skill，按七步流水线执行。

**第四步：试点验证**

第一次用，建议选一本**方法论密集、篇幅适中**的书（比如 200-300 页的商业/思维方法类），不要一上来就选《战争与和平》。

蒸馏完第一本后：
- 看看产出的 `DIGEST.md`，感受一下和传统读书笔记的差异
- 在真实场景中试着触发一两个 skill（比如真的遇到一个决策时，看"逆向思维"skill 会不会被激活）
- 根据体验调整——哪些 skill 的 trigger 太宽？哪些从来没被调用过？

### 进阶路径

| 阶段 | 做什么 | 预期收获 |
|------|------|------|
| 🌱 入门 | 蒸馏 1 本书，装到 skills 目录 | 理解"蒸馏"和"总结"的本质区别 |
| 🌿 进阶 | 蒸馏 3-5 本不同领域的书 | 体验跨领域的 skill 网络效应 |
| 🌳 高阶 | 蒸馏视频/播客/课程 | 把"被动消费"变成"能力积累" |
| 🚀 专家 | 接入 darwin-skill 自动进化 | 让 skill 随使用反馈自我优化 |

## 6. 有什么用

### 场景一：看书/视频后不再是"看过了"

**问题**：你可能看了很多书、收藏了很多视频，但真正遇到问题时还是想不起来用。

**解法**：蒸馏成 skill 后，当你遇到相关场景时，AI 会主动调用——**知识从"被动存储"变成"主动服务"**。

**具体例子**：
- 蒸馏完《思考，快与慢》→ 当你做决策时，AI 会自动提醒你"你现在可能在用系统 1 快思考，要不要切换到系统 2？"
- 蒸馏完《非暴力沟通》→ 当你要写一封可能会冒犯同事的邮件时，AI 会自动帮你改写

### 场景二：不再浪费好内容

**问题**：B 站/YouTube 上有很多干货长视频（1-3 小时），但看一次根本吸收不了。而且这些内容很可能没被 AI 训练过。

**解法**：用 video-downloader 下载字幕 → 仓颉蒸馏 → 变成可调用的 skill。

**具体例子**：
- Andrew Ng 的 26 集 AI 入门课（总时长 4+ 小时）→ 蒸馏出 **25 个可调用的 skill**
- 处理耗时：约 1 小时（不需要你看完 4 小时视频）

### 场景三：建立自己的"方法论武器库"

**问题**：不同领域的方法论散落在不同地方，没有体系。

**解法**：每读完一本好书、看完一个好课程，就蒸馏一次。日积月累，你的 skills 目录会变成一个**跨领域的决策支持系统**。

**网络效应**：skill 越多，Zettelkasten 链接越密，AI 在你遇到问题时能调用的"视角"越多。

## 7. 和你的 AI 知识体系的关系

仓颉 Skill 和你正在搭建的 AI 知识体系是**互补关系**：

| | 你的 AI 知识体系 | 仓颉 Skill |
|------|------|------|
| **定位** | 信息收集 + 学习导航 | 能力建模 + 自动调用 |
| **输入** | 抖音/推特/ GitHub 等碎片信息 | 整本书/长视频/课程 |
| **产出** | 精加工文章（人类阅读） | 可执行 Skill（AI 调用） |
| **用途** | 学习、回顾、灵感 | 在真实场景中帮你解决问题 |

**一个可能的结合方式**：
- 你在 AI 知识体系中收集到的**好书、好课程** → 用仓颉蒸馏成 skill
- 你在 AI 知识体系中整理的**方法论文章** → 可以作为仓颉的输入源
- 蒸馏出的 skill → 在后续日常使用 AI 时自动帮到你

> 💡 实际上，你的抖音采集系统已经覆盖了视频内容。如果某个视频内容足够有深度（比如你收集的那些 Claude Code 使用技巧），完全可以考虑用仓颉蒸馏出可复用的 skill。

## 8. 常见问题

**Q: 我没有书本文本文件怎么办？**
A: 可以先找 EPUB/PDF 版本，用工具（如 Calibre、markitdown）转成纯文本。视频的话，搭配 [video-downloader](https://github.com/kangarooking/kangarooking-skills/tree/main/video-downloader) skill 下载字幕。

**Q: 一本 300 页的书要处理多久？**
A: 取决于 AI 的处理速度，通常在 30 分钟到 2 小时之间。但你不需要全程盯着——阶段之间只需要你确认两次（骨架理解和入选名单）。

**Q: 蒸馏效果不好怎么办？**
A: 最常见的两个原因：
1. 阶段 0 的批判审视没做到位——导致 skill 带着作者盲点
2. 阶段 4 的压力测试没做或没认真做——导致 trigger 不准

**Q: 什么内容适合蒸馏？什么不适合？**
A: 适合：方法论密集、有可迁移框架、作者有独特见解的内容。不适合：纯叙事（小说）、纯信息罗列（教科书定义章节）、纯情感表达（散文）。

**Q: 蒸馏完的 skill 能分享给别人吗？**
A: 可以。仓颉产出的 SKILL.md 是标准格式，可以像代码一样分享、fork、改进。这也是开源的初衷。

## 附录：核心术语速查

| 术语 | 含义 |
|------|------|
| **Skill** | 一个独立的、AI 可调用的技能模块，包含触发条件、执行步骤、边界 |
| **蒸馏** | 从长内容中提取可复用的方法论，不同于"总结" |
| **RIA-TV++** | 仓颉的核心方法论：RIA（赵周拆书法）+ TV（三重验证）+ ++（面向 AI 执行的扩展） |
| **Trigger** | 触发条件——用户在什么情境下、说什么话时，AI 应该激活这个 skill |
| **Zettelkasten** | 卡片盒笔记法——原子化、链接、用自己的话重写 |
| **darwin-skill** | 让 skill 自动进化的配套工具，仓颉产出的 test-prompts.json 兼容它 |
