## 📌 一句话总结

Codex 不是聊天工具，而是一个**能直接操作你电脑的 AI Agent** -- 整理文件、制作报表、构建仪表盘、操作浏览器，不需要任何编程基础，几句自然语言即可驱动。

---

## 🔍 核心内容

### 1. Codex 是什么？和豆包 / DeepSeek 的根本区别

| 维度 | 聊天型 AI（豆包/DeepSeek） | 桌面 Agent（Codex） |
|------|--------------------------|---------------------|
| 交互方式 | 只能打字聊天，给你文字回复 | 直接操作电脑：读写文件、操控浏览器、创建软件 |
| 产出形态 | "这是整理建议"（需要你手动执行） | 自动执行完毕，直接交付成果文件 |
| 能力边界 | 语言理解与生成 | 语言理解 + 系统级操作 + 自动化执行 |

Codex 能做：整理文件、制作报表、编写周报、做 PPT、操作浏览器构建复杂软件，甚至设置好任务在你睡觉时自动运行，睡醒即完成。

### 2. 安装与初始配置

- Codex 已入驻 **微软应用商店**和 **苹果 App Store**，直接搜索安装即可
- 强烈建议首次使用修改「工作模式」为 **"日常工作"**：功能同样强大但不显示满屏技术细节，体验更友好

### 3. 核心概念：项目（Project）

Codex 直接在你的电脑上工作，需要一个**工作文件夹**，Codex 称其为「项目」。

**最佳实践**：将不同类型的工作分到不同项目文件夹中，一目了然:

```
项目 1: 咖啡店数据
项目 2: 工作汇报
项目 3: 视频制作
```

在输入框下方选择当前对话的工作项目，Codex 即可读取该项目文件夹内的所有文件来帮你完成工作。

### 4. 实战演示一：文件整理 + 数据提取

**场景**：「计算机物语咖啡馆」文件夹，内含杂乱的销售记录、发票（PDF）、库存清单、图片等各种格式的数据。

**指令**:
> "帮我把这些文件规整一下，然后把这些信息和数据提取并整理到一个 Excel 中，方便我查阅这家店的详细数据。"

**结果**:
- 自动按用途分类整理文件
- 生成详细数据汇总表（销售数据、商品排行分门别类）
- 提取 PDF 发票中的明细信息
- **关键亮点**：Codex 主动发现了两处异常 -- 交易记录缺失 + 两张发票异常（作者故意埋的坑，用于验证 AI 的审查能力）

### 5. 实战演示二：可视化仪表盘

**指令**:
> "@汇总表 请用这张表里的数据帮我制作一个可视化仪表盘，让我能轻松查看经营情况（销售、支出、成本、库存等），并分析有哪些需要关注的事项。"

**关键操作**：对复杂任务使用 **「计划模式」**，Codex 会：
1. 先规划详细的执行清单
2. 对不确定的细节主动提问确认
3. 生成计划供你审核调整
4. 确认后才开始执行

仪表盘结果包含销售、支出、成本、库存等全方位数据可视化 + 重点事项建议列表。

后续只需一句话就能调整样式，如 "请帮我换一个更现代化、直观的主题，像苹果公司那样" -- Codex 直接修改到位。

### 6. 隐藏功能：桌面宠物

在输入框输入 `/`（斜杠），选择「宠物」，桌面上会出现一个可拖拽的小宠物，实时显示当前正在执行的任务列表。

### 7. @ 文件引用

在对话框中输入 `@` 可直接引用指定文件，让 Codex 精准读取该文件内容。

## 🧠 专家升华

### 一、Codex 的架构本质：从 "AI 聊天" 到 "AI 操作员"

Codex 超越了传统 LLM 的「文本进-文本出」范式，实现了 **Computer-Use 架构**。这是桌面 Agent 与聊天 AI 之间的根本分界线：

- **聊天 AI（Doubao/DeepSeek/ChatGPT）**：以对话为核心，输出建议或文本，用户自己动手执行
- **桌面 Agent（Codex/Claude Code）**：具备文件系统 I/O、浏览器自动化、系统指令执行能力，**AI 从"大脑"变成了"大脑+手"**

这对生产力意味着什么？以前你问 AI "怎么做"，它告诉你方法然后你自己加班；现在你告诉 Codex "做这个"，它直接交付成果。这是从**知识辅助**到**劳动替代**的质变。

### 二、"项目" 设计中的 RAG 思想

Codex 的「项目」概念看似简单，实际上暗合了 **RAG（Retrieval-Augmented Generation）的核心原理**：通过将工作目录作为 AI 的检索上下文，实现了文件系统级别的语义 grounding。

- **好处 1**：边界清晰 -- 每次对话被限定在特定项目文件范围内，避免上下文污染和幻觉
- **好处 2**：可复现 -- 项目 = 文件夹，可以复制、备份、分享
- **好处 3**：渐进式 -- 不像一次性 prompt 需要把所有背景塞进上下文窗口，文件天然形成了知识增量

**进阶建议**：为项目文件夹建立 README.md，在其中写清楚项目目标、数据说明、注意事项。这相当于给 Codex 的 "System Prompt"，能显著提升执行质量。

### 三、计划模式 vs 全自主 Agent 的辩证

计划模式是 Codex 与早期全自主 Agent（如 AutoGPT/BabyAGI）的**关键差异点**：

| 模式 | 代表 | 优点 | 致命缺陷 |
|------|------|------|---------|
| 全自主 Agent | AutoGPT | 无需人工介入 | 极易跑偏、无限循环、浪费 token |
| 计划模式 | Codex Plan Mode | 人机协同、质量可控 | 需要等待确认（极低代价） |

**核心洞见**：全自主 Agent 在 2023-2024 年火了一阵后迅速冷却，恰恰是因为**缺少人机交互的校验闸门**。Codex 的计划模式找到了 Agent 落地的黄金平衡点 -- 规划阶段保留人的判断权，执行阶段放手让 AI 跑。这在 AI Agent 领域被称为 **HITL（Human-in-the-Loop）Planning**，是目前最务实的 Agent 架构模式。

### 四、演示中的隐蔽亮点：异常检测能力

作者在咖啡馆数据中故意埋坑（缺失交易、异常发票），Codex 不仅完成了整理任务，还**主动**发现了这些异常。

这背后是一个重要信号：**现代 LLM 在执行操作性任务时，会产生超出指令范围的"审查行为"**。你让它整理数据，它顺便做了数据质量检验。这种"溢出"能力意味着：你不需要把所有检查项都写在 prompt 里 -- AI 本身就有基础的数据敏感性。

**实操建议**：对于数据分析类任务，结尾加一句 "如有异常请标注" -- 用最低成本激活 AI 的审查能力。

### 五、Desktop Agent 竞争格局（2026 年中）

| 工具 | 定位 | 优势 | 适合人群 |
|------|------|------|---------|
| **Codex** | 通用桌面 Agent | 丰富的 GUI + 插件生态 + 低门槛 | 非技术用户、创作者、运营 |
| **Claude Code** | 专业编程 Agent | 强大代码能力 + 终端原生 + Claude 模型深度集成 | 开发者、工程师 |
| **Trae（字节）** | 国内替代 | 中文优化 + 国内访问便捷 | 国内普通用户 |
| **CodeBuddy（腾讯）** | 企业协作 | 腾讯生态集成 | 腾讯系企业用户 |

**选型建议**：日常办公 / 数据处理用 Codex，写代码用 Claude Code，国内网络受限场景用 Trae。不必纠结 "学哪个" -- 同类工具的操作逻辑相通，先选一个用起来。

### 六、一个被忽视的元技能

这个教程最值得注意的不是技术细节，而是**作者的演示设计**：用真实文件 + 故意埋坑 + 逐步升级任务（简单整理 → 复杂仪表盘）。这展示了一个关键心法 -- **验证 AI 能力的最好方式不是看评测，而是用你自己的真实数据去压测它**。别人的教程是别人的场景，只有你的真实工作流才能检验 AI 对你是否真的有用。

## 💪 行动清单

1. **今天就安装**：去微软商店或 App Store 搜索 Codex 安装，不要再观望
2. **改工作模式**：设置 → 工作模式 → 选「日常工作」
3. **选一个真实项目**：找一个你电脑上真实存在、有点乱的文件夹，让 Codex 整理它（别再用教程的示例数据 -- 用你自己的）
4. **掌握 Plan Mode**：下一次遇到复杂任务时，记得切换到计划模式，体验"先规划后执行"的流程
5. **建立项目结构**：把日常工作按场景分成不同项目文件夹，长期维护
6. **进阶玩法**：安装结束后继续探索 `/` 菜单中的插件和自动化工作流功能
