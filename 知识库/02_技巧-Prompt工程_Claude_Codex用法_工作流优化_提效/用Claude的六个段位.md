### 🥉 段位一：业余小白——Claude 当百度用

**典型行为**：问一个问题，得到回答，马上关掉。没有记忆，没有项目（Projects）。Claude 根本不知道你是谁、做什么的、偏好是什么。

**两个立刻升级的技巧**：

**技巧 1：让 AI 先面试你**
```
Before you answer, ask me questions until you have
all the background information needed to perform
this task properly.
```
不要上来就要答案。先让 Claude 反问你 3-5 个问题，把背景、约束、偏好全部摸清，再动手。这一步能消除 70% 以上的"答非所问"。

**技巧 2：让它自查逻辑**
```
Check your reasoning for logical flaws, then re-output
the corrected version.
```
Claude 的第一版输出往往有逻辑漏洞。一条指令让它自我审视、修正后再交付，输出质量直接跃升。

### 🥈 段位二：进阶玩家——建你的"第二大脑"

**核心动作**：使用 Claude 的 **Projects（项目）** 功能。

**高阶玩法——别再自己写指令**：
1. 新建一个 Project
2. 让 Claude interview 你，而不是你去写 prompt
3. 把你的过往成功案例、工作流模板、风格偏好全部喂进项目文件库
4. 每次在这个 Project 里对话，Claude 自动加载全部上下文

**效果**：AI 输出的每一句话都像你自己写的——语气、格式、决策偏好，比你的助理还懂你。

**实操举例**：
- 每次做 YouTube 视频，Project 里已有选题框架、脚本模板、封面风格
- 每次写销售邮件，Project 里已有客户分类、话术库、过往成功案例

### 🥇 段位三：高效狂人——AI 替你"干体力活"

**核心动作**：连接真实工作数据源——邮箱、Google Drive、Slack、日历、Notion。

**典型场景**：
- 不再在网页之间复制粘贴
- 把邮箱、日历、云盘通过 MCP (Model Context Protocol) 接入 Claude
- AI 每天自动扫描全部信息源，生成三份老板专属早报

**早报内容示例**：
1. **紧急事项**：需要今天处理的消息和截止日
2. **进展概览**：团队周报、客户反馈、项目状态
3. **机会雷达**：新合作邀约、LinkedIn 动态、行业信号

> 到这个段位，你不再是打工人——AI 是你 24 小时不睡觉的初级助理。

**核心工具**：Claude Code Skills / Agent Skills 规范

**操作路径**：
```bash
# 注册官方 Skills 市场
/plugin marketplace add anthropics/skills

# 安装示例 Skills
/plugin install example-skills@anthropic-agent-skills
```

**关键观念转变**：
- 你不再"用"AI，你"部署"AI
- 每个 Skill 就是一个数字员工：独立文件夹 + SKILL.md 指令 + 元数据
- Anthropic 已开源数百个参考 Skill（Apache 2.0），覆盖设计、测试、企业沟通等

**实操**：把自己重复做的任务抽象成 Skill，Claude 在后台自动执行，你只审核结果。

### 👑 段位五：降维建构者——自然语言就是最强编程语言

**这是普通人和超级个体的分水岭。**

**核心洞察**：你不需要会写代码。自然语言就是图灵完备的编程语言。

**真实案例**：一位从未写过程序的家庭主妇，用自然语言描述了房产管理、车辆维护、家庭预算三条工作流，Claude 直接搭建出完整管理系统。

**高阶指令——/plan 模式**：
```
/plan [你的需求描述]
```
1. 你把想法全部倒出来，不要整理
2. Claude 先打出完整技术方案和架构框架
3. Claude 反问你澄清模糊点
4. 你审过框架、确认无误
5. Claude 才开始写代码

**Plan 模式示例**（视频中的真实案例）：
- 需求：Lead Magnet Quiz App（潜在客户引流测验应用）
- Claude 先确认技术栈（Next.js）、生成方式（AI 实时生成 vs 预设答案）、邮件流程
- 然后输出完整架构：Hero → 测验表单 → AI 结果生成 → 邮箱门控 → 品牌 PDF 下载 → 邮件序列
- **框架盘清楚之后，一行代码都不需要你写**

### 🚀 段位六：终极指挥官——一人公司的 AI 军团

**最高境界：你手里不再是一个工具，而是一个自动运转的数字帝国。**

**架构**：

```
                    🧠 你（AI 总裁）
                         │
              ┌──────────┼──────────┐
              │          │          │
         🤖 开发 Agent  🤖 运营 Agent  🤖 质检 Agent
              │          │          │
         ┌────┴────┐     │     ┌────┴────┐
         │         │     │     │         │
       写代码   修Bug   发邮件  逻辑审查  风格审查
```

**运转方式**：
1. 你设计规则和工作流
2. AI Agent 们自动开会协作、互相调用
3. 质检 Agent（Critique Agent）审查每个输出
4. 最终报告推到你面前——你喝着咖啡审阅即可

**核心心法**：每个 AI Agent 专注一个领域（如开发、客服、质检），通过共享 Memory 总线通信。你只处理 AI 处理不了的例外。

**视频作者的 Pro Tip**：永远设一个"Critique Agent"，让它在主力 Agent 输出之后做逻辑审查、风格审查、事实核查——这个质检层是质量的生命线。

## 🧠 专家升华

### 一、技术深度分析：六个段位背后的 AI 工程原理

#### 段位一的本质：Context Deficiency Problem（上下文缺失问题）

研究数据表明，73% 的 AI "不好用"反馈源于上下文不足，而非模型能力不够。段位一的"让 AI 面试你"本质上是 **Clarification-Driven Generation（澄清驱动生成）**——将隐式上下文转化为显式约束。这个技巧的背后是 **Chain-of-Thought 的前置化**：不是在推理阶段才展开思维链，而是在需求输入阶段就让模型建立完整的问题空间。

**更优方案**：不要只用一次反问。设计一个结构化的上下文注入模板：

| 维度 | 必须提供的信息 |
|------|---------------|
| Who | 你是谁、角色、经验水平 |
| What | 具体任务、成功标准 |
| Why | 为什么做、背景动机 |
| Constraints | 限制条件、预算、时间线 |
| Format | 输出格式、长度、风格 |
| Examples | 2-3 个理想输出样例 |

#### 段位二的本质：RAG + Personalization Pipeline

Projects 功能本质是轻量级 RAG（检索增强生成）。但多数人的问题是 **信息堆砌而非信息架构**。你喂进去的不是越多越好——是越有结构越好。

**更优方案——三层知识架构**：

```
📁 Project 文件库
├── 🔴 原则层（10% 上下文）  → 不可变：品牌指南、决策红线、核心价值观
├── 🟡 模板层（30% 上下文）  → 半稳定：工作流模板、脚本框架、邮件结构
└── 🟢 示例层（60% 上下文）  → 可替换：过往成功案例、理想输出样本
```

**实操**：创建 `STYLE.md`，记录你的语音特征、格式偏好、决策启发式——把它设为 Project 的系统级指令，比堆 20 个案例文件更有效。

#### 段位三的本质：Tool-Use Orchestration（工具编排）

接入邮箱、日历、云盘不是目的——**信息降噪和优先级排序**才是。原始数据涌入只会制造噪音。

**更优方案——智能过滤管道**：

```
全部信息源 → 紧急度打分(0-10) → 相关性打分(0-10)
    → 过滤阈值(总分<12 不展示)
    → 自动分类：需回复 / 需知晓 / 存档
    → 生成三层早报
```

**行业位置**：这正是 AI Executive Assistant 赛道（如 Motion、Reclaim.ai、Superhuman AI）的核心能力。你不需要等产品——用 MCP 协议 + n8n 工作流可以自己搭。

#### 段位四的本质：Agent Skills as Micro-Services

Skills 本质是将 LLM 能力封装为可组合、可复用、可版本控制的微服务。这不是"保存几个 prompt 模板"——这是建你的 **AI 能力中台**。

**更优方案——Skill 工程规范**：

```markdown
# SKILL.md 最小可行模板
## 元数据
- 名称、版本、依赖、触发条件

## 输入规范
- 必须字段、可选字段、类型约束

## 核心逻辑
- 步骤 1 → 步骤 2 → 步骤 3

## 输出规范
- 格式、Schema、示例

## 错误处理
- 常见失败模式 + 回退策略

## 测试用例
- 3 个标准输入 → 预期输出
```

**行业位置**：这是 Agent-as-a-Service 范式的前沿。OpenAI 的 GPTs、Anthropic 的 Skills、LangChain 的 Tools 都在朝这个方向收敛。先建好自己的 Skill 库，就是建竞争壁垒。

#### 段位五的本质：Specification-Driven Development（规约驱动开发）

这是软件工程 50 年经验在 AI 时代的降维应用。**写好规约比写好代码更重要**——因为代码是 AI 写的，但规约是你写的。

**更优方案——三层 Plan 模式**：

```
Layer 1: 需求规约（What & Why）
  → 用户故事、验收标准、边界条件

Layer 2: 架构规约（How）
  → 技术栈、数据流、组件树、API 契约

Layer 3: 测试规约（Verify）
  → 5 个核心测试用例、异常路径
  → AI 先写测试 → 再用测试驱动实现
```

**实操技巧**：要求 Claude 在 `/plan` 中先定义 JSON Schema 输出格式，这样后续代码可以精确解析 AI 输出——这是从"AI 写代码"到"AI 驱动的可维护系统"的关键一跃。

#### 段位六的本质：Multi-Agent Orchestration with Human-in-the-Loop

这是目前 AI 工程的最前沿——**Agent 编排**。核心挑战不是让 Agent 工作，而是让多个 Agent **协作不出错**。

**技术架构参考**：

| 模式 | 适用场景 | 实现工具 |
|------|---------|---------|
| Supervisor 模式 | 一个主管 Agent 分配任务、汇总结果 | LangGraph, CrewAI |
| Peer-to-Peer 模式 | Agent 之间直接通信协作 | AutoGen |
| Pipeline 模式 | A→B→C→D 顺序执行，每步有质检门 | n8n, Temporal |
| Hierarchical 模式 | 总裁→总监→执行，多层决策 | 自定义编排 |

**关键设计原则**：
1. **共享 Memory 总线**：所有 Agent 读/写同一个上下文池，避免信息孤岛
2. **Human-in-the-Loop 门控**：关键决策点（> $100 花费、对外发布、法律相关）必须人工审批
3. **质检 Agent 是必选项**：每个 Agent 的输出经过 Critique Agent 审查后才能进入下一环节
4. **失败回退链**：每个环节有超时 + 重试 + 升级机制

### 二、行业位置：大多数用户卡在哪里？

基于对用户行为的观察，各段位分布大致如下：

| 段位 | 占比 | 卡点 |
|------|:---:|------|
| 1 业余小白 | ~60% | 不知道 AI 能记住上下文，把"打开网页问一句"当作 AI 的全部能力 |
| 2 进阶玩家 | ~25% | 会 Projects 但不会结构化知识，堆文件而不建体系 |
| 3 高效狂人 | ~10% | 知道可以接工具但不知道 MCP 怎么配 |
| 4 赛博包工头 | ~4% | 习惯手动操作，没有"封装复用"的工程思维 |
| 5 降维建构者 | ~1% | 心理门槛——"我不会写代码"就停了，不知道自然语言够用 |
| 6 终极指挥官 | <0.1% | 需要系统架构思维和 Agent 编排知识，目前社区教程极少 |

**你不需要一步到位**。每升一级，效率提升 3-10 倍。从段位 1 升到段位 2 只需要 30 分钟（建一个 Project），但效率提升立竿见影。

### 三、实操建议：30 天升级路线

| 周次 | 目标段位 | 每日投入 | 核心动作 |
|:---:|:---:|:---:|------|
| 第 1 周 | 1 → 2 | 10 min/天 | 建 3 个 Project + 写 STYLE.md + 每次对话前用"反问问句" |
| 第 2 周 | 2 → 3 | 20 min/天 | 配置 MCP 连接邮箱 + 日历 + 创建第一条自动化早报 |
| 第 3 周 | 3 → 4 | 30 min/天 | 识别 3 个重复任务 → 封装为 Skill → 配置后台自动运行 |
| 第 4 周 | 4 → 5 | 45 min/天 | 用 /plan 模式完成一个真实项目 + 学会 JSON Schema 约束输出 |

**段位 6 需要额外 2-4 周的 Agent 编排学习**，建议先用 cc-fleet 或 LangGraph 搭建一个 2 Agent 的最小可行系统（如：开发 Agent + 质检 Agent）练手。
